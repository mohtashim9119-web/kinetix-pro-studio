## Key Invariants

Non-negotiables. Future work — especially the Architecture Shift active task — must not break these without a deliberate, documented decision.

- **(a) Sync timing is regression-locked.** `src/services/syncTiming.test.ts` (154 vitest tests in this file alone as of `86ffc5a`, up from the original 8 added in commit `05398f4` "lock sync timing pipeline with regression test") plus the `sync-known-good-2026-06-20` tag protect the sync/anchor timing pipeline. Tag message: *"Known-good single-click ms-correct sync. Baseline for per-slot re-sync work. Restore/bisect target if sync drifts."* **Superseded as the active bisect target by `sync-known-good-2026-07-29`** (the final WS6 docs-sweep commit, on top of the token-stealing fix `86ffc5a` — see the Restore tag row above) — the sync system was fully rewritten (Hirschberg aligner, coverage metric + abort gate, skip-unmatched, snap boundaries, stage-direction/speaker-label stripping, per-segment temporal-bounding rescue) since the 2026-06-20 tag was cut, so the newer tag is the correct restore/bisect target for any sync drift going forward; the 2026-06-20 tag is retained only as the historical pre-rewrite baseline.
- **(b) Σ content-segment duration = voiceoverDuration.** This applies to content segments only — every `VideoSegment` in `project.segments` is content (no in-array headings exist as of Path B Phase 7, 2026-07-08). Total content-segment duration must always equal the voiceover's duration. Transition overlaps cancel pairwise by construction (Path B cross-fade design — see `docs/history.md`'s Decisions Log, 2026-05-25), so this holds without special-casing `App.tsx`. Headings are excluded entirely from this invariant — they own no timeline seconds (see (c)). This isn't theoretical: removing `splitAudio` in Heading Round 5 broke an earlier version of this invariant and cost 4 rounds of drift-bug fixes before headings were rebuilt as pure overlays.
- **(c) Headings are a separate top-level `HeadingOverlay[]` layer (`project.headings`), not segment-array entries.** Path B (see `docs/history.md` → "Path B — Separate Heading Layer — Design Decisions (Archived)") replaced the old in-array `isHeading`/`headingConfig` system entirely in Phase 7 (2026-07-08) — `VideoSegment` carries no heading fields anymore. A `HeadingOverlay` has a fixed absolute `time` that never moves on re-sync (a clamp+`needsReview` flag handles a re-sync that shrinks past it); it participates in no segment timing math and is composited on top of whichever segment(s) fall within its time range at render/export time.
- **(d) Transcription cache validity is keyed by file identity, not asset id.** `getFileIdentity(file) = \`${file.name}|${file.size}|${file.lastModified}\`` (`src/services/syncEngine.ts:216`), cached as `Project.lastTranscribedFileIdentity` (`src/types.ts:215`). Necessary because every file-stage event mints a fresh `Asset` id even when the user re-picks the identical file — id/reference equality can't catch a re-stage, but name+size+lastModified can.
- **(e) `anchorSource` provenance only ever moves one direction.** `'whisper'` = precise audio alignment; `'estimate'` = character-weight approximation that Whisper can still realign later. An anchor may be demoted `whisper → estimate` but is never promoted back, regardless of text changes (enforced by `syncTiming.test.ts`).
  - *Post-3c follow-up note — closed 2026-06-24 (post-3d-2):* `anchorSource` is confirmed effectively write-only — no production code branches on `'whisper'` vs `'estimate'`. Still written by `parseProjectData`, `applyAnchorBasedTiming` PASS 1, `distributeSegmentTimes`, and `handleInsertHeading` (PASS 2, the other writer, was deleted in 3d-2). Now documented directly in the `anchorSource` doc-comment in `src/types.ts`; no further cleanup planned.

| 2026-07-29 | **WS6 — per-segment temporal-bounding rescue for the token-stealing bug class, shipped as a rescue layered on the unchanged global aligner (design deviation from the literal spec, justified below).** Root cause (verified via temporary production instrumentation, since removed): the Hirschberg aligner's single global alignment has no temporal awareness — an overflowing segment's own real trailing words can land, in the transcript, chronologically AFTER a neighboring segment's real content; monotonicity then permanently blocks that neighbor from reaching backward to its own words, even though nobody ever truly claims them. Reproduced directly (scene 152/153 shape): segment 153 landed at 0/3 matched words despite "linen from flax" being genuinely spoken. **Design deviation:** the task spec called for replacing the global pass with fully independent per-segment bounded alignment (Parts 1-3). Implemented literally first, then rejected after it reopened the exact bug class an earlier workstream (§3.1) closed — with no anchor data (several existing adversarial unit tests deliberately have none), independent per-segment windows degenerate to "the whole timeline," and two segments sharing an exact word can each independently and greedily claim it with no cross-segment coordination, decided by processing order rather than correctness. Shipped design instead: the global pass is **completely unchanged**; a targeted rescue runs afterward, firing ONLY for a segment left at zero true matches, ONLY when it has a real `anchorStart`, and it may claim ONLY transcript words `globallyClaimed` proves nobody else's global pass already matched. This preserves every pre-WS6 test's exact behavior (global-optimality tests, repeated-phrase disambiguation, shared-word tie-breaks) while fixing the reported bug, because a substitution — which is what actually consumes the stolen words in the real bug — never enters `matchedSubjectOf` and so was never protected by global exclusivity in the first place. **C3 (monotonic carry-forward) also overridden:** the spec's literal time-floor (`prevAnchor + gap`) was implemented, tested against the real repro, and found to actively block the fix — the overflowing segment's own true trailing match is definitionally positioned AFTER the stolen tokens, so a floor derived from it re-excludes them. Fix: replaced the plain `useRef` canvas ref with a `useCallback` callback-ref (`canvasNode` state, internal to the hook, exposed as `UseGlPreviewResult.canvasRef`); added `canvasNode` to both the GL-init effect's and the per-tick render effect's dependency arrays, so a canvas that mounts after `enabled` was already true correctly retriggers both, regardless of prior `enabled` transitions. `PreviewStage.tsx` updated to attach `ref={glPreview.canvasRef}` instead of holding its own `glCanvasRef` — the only other file touched. `tsc --noEmit` clean, `vitest` **414/414** (up from 409 — 4 new tests). **Honest test-coverage note:** the new tests are pure re-statements of React's documented dependency-array shallow-compare (`Object.is` per entry) applied to the exact before/after shapes this fix changes — they do NOT render the hook or mechanically prove React itself re-invokes the effect, because this repo has no jsdom/happy-dom/@testing-library/react/react-test-renderer (confirmed absent from `node_modules`; same limitation this codebase has flagged before for `useWebCodecsPreview.test.ts`/`useGlPreview.test.ts`). **Verification was manual, in the real Tauri app**, not automated: user confirmed both a fresh cold load and the paused-cold-load variant (toggle already ON, project opened while paused, never played) now render correctly with no reload or toggle workaround needed. Closes the Bug 4 entry that was in Deferred Known Bugs. |
